Why we built it

Reviews are where good intentions run out of time.

Everyone agrees code review matters. Then it’s Thursday afternoon, there are eleven pull requests waiting, and the person who knows that part of the code is on holiday.

The bugs that slip through aren’t exotic. A loop that runs one step too far. A check that’s missing on one path. A library with a known hole in it.

Revylx is the colleague who has time to look at every change, every time. It doesn’t replace your reviewers. It gives them a head start, so their attention goes where it’s needed most.

How it fits into your day

It works where your team already works.

Nothing to install on anyone’s laptop for pull request reviews. Connect once, and every pull request gets a reviewer.

  1. Connect your code hostGitHub, GitLab (including your own GitLab server), Bitbucket or Azure DevOps. Pick the repositories you want reviewed.
  2. Open a pull request as usualRevylx posts a short summary with an overall risk level and a file-by-file walkthrough, then comments on the exact lines that need attention.
  3. Push again, and it keeps upLater pushes are reviewed on what changed since last time, repeat comments are left out, and threads that no longer apply can close themselves.
  4. Accept a fix, or don’tMany comments carry a suggested change you can apply in one click. Or ask Revylx to make the fix for you: it commits to the branch, checks its own work, and opens a separate pull request when it can’t push directly.

What every review looks for

The things that bite you after you ship.

Each comment is marked critical, high, medium or low, so the important ones never get lost among the nitpicks. A second pass weeds out weak findings before they reach you.

Bugs and edge cases

Off-by-one loops, missing checks, wrong conditions and the paths nobody tested.

Security problems

Injection risks, unsafe patterns and leaked secrets, using well-known scanners alongside its own reading of the code.

Risky dependencies

Libraries with published vulnerabilities, and whether your code actually reaches the risky part, so you don’t chase warnings that don’t matter.

Context from your codebase

It indexes your repository, so it understands how a change affects the code around it, in more than 25 languages and formats, from TypeScript and Python to Go, Rust, Java, C++ and Terraform.

A clear go or no-go

A quality-gate status on every pull request, so your branch rules can wait for a clean review.

Gets better with you

Rate a comment with a thumbs up or down, apply or dismiss a fix, and it learns what your team cares about.

Talk to it in the pull request

Just mention @revylx.

Ask a question in plain words and it answers using your codebase. Or use one of these. Anyone can ask questions; changes to code need write access, and commands from outside contributors wait for a maintainer.

SayWhat happens
@revylx reviewReviews the latest changes. Add --deep for a slower, more thorough look.
@revylx re-reviewStarts over and reviews the whole pull request from scratch.
@revylx focus securityReviews again with one topic in mind, such as security or performance.
@revylx auto-fixFixes what it found and commits it, or opens a separate pull request. Try --dry-run to see the change first.
@revylx generate-testsSuggests tests for the change, in the framework your project already uses.
@revylx revertUndoes a commit Revylx made. It never touches anyone else’s.
@revylx + your question“Why does this function retry three times?” Answered from your codebase.

In your editor

A quick second opinion before you push.

Extensions for VS Code and JetBrains IDEs bring Revylx closer to where you write code. They’re deliberately lighter than the pull request review, and we want to be clear about how.

Quick checks as you save

Instant, local checks for leftover debug code, unused imports and similar slips, on TypeScript and JavaScript. Nothing leaves your machine.

Review this file

One shortcut sends the file you’re working on for a full review, with findings in your editor’s problems list. Included each month on paid plans.

What it doesn’t do yet

The editor review looks at one file on its own, without the rest of your repository, and it doesn’t apply fixes for you. The full, context-aware review happens on the pull request.

Make it yours

Your rules, your tools, your team.

Every team reviews differently. Revylx bends to yours instead of the other way round.

A settings file in your repo

Add .revylx.yml to give it house rules in plain words, set the lowest severity worth mentioning, skip folders, or ask for deep reviews every time.

Team-wide rules

Write rules once in the dashboard and every repository follows them. Choose a thorough or a focused review style.

Alerts where you talk

A Slack message when a review finishes, and signed webhooks so your own systems can react to reviews, comments and fixes.

A dashboard for the team

Every review in one place, with trends, usage, the state of your repository index, and audit logs of who changed what.

Roles that make sense

Owners, admins, members and viewers, with seats managed in one place.

Run it on your own servers
